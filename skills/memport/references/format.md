# MMF v1.1 — MemPort 记忆包格式规范

**定位**:跨工具记忆交换格式。设计目标是**省 token、可 diff、可校验、确定可解析**——同一批记忆,JSONL 的对象键大约要吃掉 40~60 token/条,MMF 只要 8~12 token/条。

文件后缀 `.mem`,UTF-8(无 BOM),行尾 LF,一条记忆一行。

> v1.1 相对 v1 新增三列 `vf`(有效期起)/`vt`(有效期止)/`st`(持续性)。
> **v1 包仍可被解析**:头部自描述列序,缺列按 `-` / `-` / `?` 补齐。导出侧应尽量写 v1.1。

---

## 1. 文件结构

```
#memport 1.1
#src=trae;project=rewrite-agently;exported=2026-09-12T10:30+08:00;count=3;sha256=9f2c1ab73d05
#cols=type|created|updated|vf|vt|st|cf|rw|tags|content
pe|2026-08-01|2026-08-01|-|-|t|0|0|hall:general;src:~/.trae/memories/rules.md#L2|命令执行优先走 WSL,能在 WSL 完成的构建/测试优先用 wsl-runner
wt|2026-09-01|2026-09-12|2026-09-01|-|o|0|0|hall:work;scope:dsh-layered-memory|dsh-layered-memory 补齐 EmbeddingManager 的 getEff 接线
wf|2026-09-01|2026-09-01|2026-09-01|2026-09-01|p|1|0|hall:work;scope:dsh|官方 DSH 的 LOCALE_IDS 只有 zh/en,ja/ko 字典随包发布但客户端无法选中
```

- 第 1 行:`#memport <版本>`(`1` 或 `1.1`)。
- 第 2 行:头部键值,`;` 分隔。`src`(来源工具,必填)、`project`、`exported`(ISO8601 含时区)、`count`(记录行数)、`sha256`(所有记录行以 `\n` 连接后的 SHA-256,可取前 12 位)。未知键原样保留、不报错。
- 第 3 行:`#cols=` 列声明。**必须声明**;缺省按默认列序解析并告警。`content` 必须是最后一列。
- `#` 开头为元信息行,空行忽略,其余行均为记录。

## 2. 列定义(默认列序)

| 列 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `type` | 是 | 见 §3 类型码 | 缺省或非法值 → 导入时回落 `ep` |
| `created` | 是 | 见 §4 | **记录时间**:该记忆首次进入记忆库的时间 |
| `updated` | 是 | 见 §4 | **变更时间**:最后一次被补充/改写的时间(未变过 = created) |
| `vf` | 是 | 见 §4 | **有效期起**:该事实在真实世界开始成立的时间;`-` = 未知/不适用 |
| `vt` | 是 | 见 §4 | **有效期止**:该事实停止成立的时间;`-` = **尚未结束或未知** |
| `st` | 是 | 见 §5 | **持续性**:`p`/`s`/`o`/`t`/`?` |
| `cf` | 是 | `0`/`1`/`?` | **是否冲突**:`1`=与库内既有记忆矛盾且未裁决 |
| `rw` | 是 | `0`/`1`/`?` | **是否被改写**:`1`=本条已被后续条目取代/改写过 |
| `tags` | 是(可空) | `k:v` 以 `;` 分隔 | 见 §6 |
| `content` | 是 | 1~600 字符,单行 | 见 §7 书写规范 |

## 3. 类型码

| 码 | 全名 | 适用 |
| --- | --- | --- |
| `pe` | persona | 用户/团队的身份、长期偏好、性格与沟通方式 |
| `ep` | episodic | 发生过的事件、经历、过程性事实 |
| `in` | instruction | 用户显式下达的规则/禁令/偏好指令 |
| `wf` | work_fact | 项目与外部世界的稳定事实(版本、路径、结论) |
| `wt` | work_task | 待办、任务、进行中的工作项 |
| `wm` | work_method | 可复用方法、SOP、踩坑与对策 |
| `wa` | work_artifact | 产物与其落点(文件、报告、构建物) |

导入侧接受裸全名(`work_fact` 等)与厂商自有分类名;厂商分类必须按 `references/export.md` 的映射表转换后再写入 `type` 列,**不允许**把厂商分类名原样塞进类型列。

## 4. 时间列:四条轴,不要混用

这是本格式最容易出错的地方。**四个时间概念互不替代**:

| 轴 | 列 | 回答的问题 | 典型值 |
| --- | --- | --- | --- |
| 记录时间 | `created` | 这条记忆**什么时候进的库**? | 导入/抽取时刻 |
| 变更时间 | `updated` | 这条记忆**最后一次被改是什么时候**? | ≥ created |
| 有效期 | `vf` / `vt` | 这条事实**在真实世界里什么时候成立**? | 可以是过去、现在、将来 |
| 持续性 | `st` | 这条事实**是时点、区间、还是仍在持续**? | 见 §5 |

**反例(必须避免)**:把"2026-03 在 A 项目"这条事实的 `created` 写成 `2026-03`。`created` 是入库时间;`2026-03` 属于 `vf`。

时间书写精度按真实精度,不要补零伪造:

| 形态 | 精度 | 示例 |
| --- | --- | --- |
| `YYYY-MM-DDTHH:MM:SS+HH:MM` | exact | `2026-09-12T10:30:00+08:00` |
| `YYYY-MM-DDTHH:MM` | minute | `2026-09-12T10:30` |
| `YYYY-MM-DD` | day | `2026-09-12` |
| `-` | unknown / 不适用 | |

- 只有日期时,导入侧按当日 00:00(本地时区)落库,并记 `createdPrec: "day"`。
- `-` 时导入侧用导入时刻落库并记 `createdPrec: "unknown"`——**不伪造原始时间**。
- `updated` 早于 `created` 视为脏数据,按 `created` 处理并告警。
- `vt` 早于 `vf` 视为脏数据,按 `vf` 处理并告警。

## 5. 持续性 `st`:它决定一条记忆会不会"过期"

| 码 | 名称 | 含义 | 时间行为 |
| --- | --- | --- | --- |
| `p` | point | **时点事件**:某时刻发生过的事 | `vf`≈`vt`;历史事实,**永不被"取代"**,后来者不能改写它的有效期 |
| `s` | span | **已结束的区间**:有明确起止的持续状态 | `vf`/`vt` 都应有值;历史区间,同上不可被改写 |
| `o` | open | **仍在持续**:目前成立、尚未结束的状态 | `vt` 应为 `-`;被矛盾事实取代时,由系统**闭合 `vt`** 并标 `rw=1` |
| `t` | timeless | **无时间性**:恒真的规则/偏好/方法 | 不参与时效衰减,`vf`/`vt` 通常都是 `-` |
| `?` | unknown | 未判定(默认值;v1 包无此列时也落这里) | 不参与"是否闭合"的判定,只当普通事实 |

**判定的唯一依据是"这个事实会不会随时间改变真值"**:

| 例子 | st | 理由 |
| --- | --- | --- |
| 用户是运维工程师转型全栈开发 | `t` | 身份/长期偏好,不随时间失效 |
| `pnpm` 首次交互可用 `--yes` 规避 | `t` | 工具行为,恒真规则 |
| 用户目前在做 rewrite-agently 的记忆插件 | `o` | 现在成立、将来会变 |
| dsh-layered-memory 存在 `getEff` 未接线的缺口 | `o` | 缺陷状态,修好即失效 |
| 2026-09-01 完成了 dsh-perm-gate 的 git 历史重建 | `p` | 时点事件 |
| 2026-03~06 在 A 项目做终端适配 | `s` | 已结束的区间 |

**为什么不是单纯的布尔**:布尔"是否持续"无法区分「时点事件」与「已结束区间」(两者都不持续,但前者的 vt 无意义、后者的 vt 是关键信息),也无法表达「仍在持续」与「永不过期」的差别——而这两者的时效行为完全相反。若上游只能给布尔,映射为:持续 → `o`(仍在持续)否则 → `p`。

## 6. tags 键

| 键 | 含义 | 示例 |
| --- | --- | --- |
| `hall` | 粗分类通道 | `work` / `relationships` / `general` / `finance` / `journey` |
| `src` | 源文件定位(可带 `#L行号`) | `~/.trae/memories/rules.md#L2` |
| `id` | 源工具内的稳定 id | `sha256:9f2c1ab7` |
| `ver` | 源侧版本号 | `3` |
| `prio` | 优先级(默认 80) | `85` |
| `scope` | 作用域(仓库/项目/模块) | `dsh-prime-memory` |
| `key` | 主体键(用于跨条冲突比对) | `dsh:locale` |
| `sup` | 本条取代了哪条(源侧 id) | `mem-abc123` |

未知键保留不动。`src` 是**溯源关键**:导入后每条记录都要能靠它回到原始文件。

## 7. content 书写规范(节省化的核心)

1. **一条 = 一个可独立成立的事实**。脱离原上下文仍能判断真伪;否则拆条或补足主语。
2. **正文不写时间**——时间由 `created`/`updated`/`vf`/`vt` 承载。禁止"昨天""上周""2026-09-01 时"。
3. **正文不写来源**——来源由 `tags.src` 承载。
4. **不写过程与对话**。禁止"我们讨论了""用户说""经过分析"。
5. **目标长度 ≤ 100 字符**(中文)/ ≤ 200 字符(英文);上限 600。
6. **不可压缩的部分必须原样保留**:路径、命令、版本号、标识符、报错原文、文件名。
7. **去代词**:把"它/这个/那边"换成语义完整的主语。
8. **矛盾要留痕**:若该条是对更早认知的修正,用 `rw=1` 并在正文中写清新旧关系。

反例 / 正例:

| 反例 | 问题 | 正例 |
| --- | --- | --- |
| 用户说他之前做运维,现在想转全栈,昨天聊到还想做 3DGS | 过程+时间+代词 | 用户是运维工程师转型全栈开发,目标岗位为云深处科技 3DGS 算法研究(`st=t`) |
| 根据 workbuddy 的日志,remotion 那个项目里 pnpm 要加 --yes | 来源+模糊指代 | pnpm 首次交互确认可用 `pnpm --yes` 规避(`st=t`) |
| dsh-prime-memory 插件有很多问题需要修复 | 不可判定 | dsh-prime-memory 的 `importLegacy` 只读 `l1/records.jsonl`(`st=t`) |

## 8. 校验规则(导入侧强制)

`memport.py validate` 执行;任一 error 即拒绝整包:

| 级别 | 规则 |
| --- | --- |
| error | 列数与 `#cols` 不符;`count` 与实际记录行数不符;`sha256` 不符;`cf`/`rw` 非 `0/1/?`;`st` 非 `p/s/o/t/?`;`content` 空或 <4 字符;包内存在内容重复(哈希相同);未知包版本;包内无记录 |
| warning | 未知类型码;`content` > 600 字符;`updated` < `created`;`vt` < `vf`;`st=o` 却给了 `vt`;`st=p` 却缺 `vf`;`content` 非最后一列;未声明 `#cols`;v1 包缺 `vf`/`vt`/`st` 列 |

**包内去重是导出的责任**:同一事实在一个包里出现两次即判 error。
