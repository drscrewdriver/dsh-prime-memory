# 图谱演进阶梯与可重建性前提

背景：图谱是本插件里唯一"看起来像事实源、其实不是"的子系统。它由 L1 记录投影而来
（`pipeline/graph.ts` → `store/graph-store.ts`），却被检索链路当作**承重部分**使用
（§D 第 3 路 `graphLane`）。把一个**不可重建**的派生结构接进检索主链路，等于把脆弱性
引入主链路；而"将来要不要上真正的图数据库"这个决策，其成立条件也完全取决于
"图谱能不能被重建"。故本节在接入图谱检索路**之前**先钉住可重建性前提。

决定：

1. **图谱是可重建的派生投影，不是事实源**。这是本 ADR 全部结论的地基。
   证据是两条结构性设计：
   - `graph_projected_records(record_id, projector_version)` —— 已投影版本对账表；
   - `graph_projection_jobs` / `graph_job_records` —— 可重放的投影队列。

2. **可重建性的正确层次是「L0 事实源 → L1 → 图谱」，不是「L1 快照 → 图谱」**。
   **全量重放**（从 L0 重推 L1，再重投影图谱）可重建全部内容，**含 `archived` 墓碑**；
   而**仅由当前 L1 快照重建则丢失墓碑**——`markSourcesDeleted`（`graph-store.ts:659-698`）
   按设计**保留**来源已从 L1 删除的墓碑行，这类行**不可由当前 L1 快照复原**。
   依据：`pipeline/rebuild.ts:2` 的重建定义即「从 **L0 事实源**重新推导 L1/L2/L3」；
   `sqlite.ts` 的 `clearL1()` 在清空 L1 时一并清空图谱表族（图谱与 L1 同生命周期）。
   **含义**：T4 换引擎时必须走**全量重放**路径（或显式接受墓碑丢失），
   **不可假设"从 L1 快照重建即可"**。这是本条结论的成立条件之一。

3. **因此，当前不引入图数据库不会造成将来锁死**。这是"不引入"这一决策成立的**核心依据**，
   而不只是性能理由——既然图谱随时可换、且换法是**重建而非迁移**，
   "先用 SQLite 顶住"就不构成技术债。

4. **演进阶梯按阈值触发，不按需猜测**：

   | Tier | 能力 | 存储 | 触发阈值 | 成本 |
   |------|------|------|---------|------|
   | **T0** | 邻接表 + 字段加权打分（现状） | SQLite | nodes 10²~10³ | 已有 |
   | **T1** | TS 内存 BFS/DFS：k-hop 邻域、最短路径、连通分量 | **不变** | nodes ≤ ~10k / edges ≤ ~100k | 纯 TS，零 schema 变更 |
   | **T2** | 递归 CTE（不物化全图） | **不变** | 图装不进内存 | 复杂 SQL + 手工防环 |
   | **T3** | 闭包表 / 物化路径（传递闭包预计算） | **不变** | 高频多跳重复查询 | 写放大，边变更需维护 |
   | **T4** | 嵌入式图引擎（**Kuzu 优先**，非 Neo4j） | 换引擎 | T1–T3 全部不足 | 原生依赖，破坏自包含 |

   **T1 的量级判断**：10 万条边 × ~100 字节 ≈ 10 MB，整图入内存无压力。
   **k-hop 遍历、最短路径、"实体 A 与实体 B 有何关系"这类需求，T1 即可满足，无需任何
   schema 变更。** 需要 T4 的门槛远高于实际可能触达的规模。

5. **T4 选型倾向 Kuzu 而非 Neo4j**：本插件的核心交付约束是**自包含**
   （`files` 白名单 + 无外部服务依赖）。Kuzu 是**嵌入式**图引擎（进程内、无服务端），
   Neo4j 需要独立服务进程——后者会直接违反自包含约束，且把一个可重建的派生投影
   升级成"必须运维的服务"，代价与收益完全不成比例。
   **注意 T4 的代价同样是确定的：原生依赖会破坏自包含**——这是 T4 门槛必须高的原因之一。

6. **T1 的触发阈值与既有判断衔接，不另立一套**：
   `graph/search.ts` 头部注释已写明「图谱节点量级…百~千级，在此直接内存打分即可，
   不建倒排索引（**>2k 节点再考虑预建**）」。**2k 是预建检查点，10k 是 T1 上限**，
   两者同处一处注释，避免"两个数各说各话"。
   **诚实标注**：10k / 100k 是**内存占用推算的估算值，非实测**。

7. **唯一现在就该做的保险：图谱可重建性冒烟测试**（`tests/graph-rebuildability.test.ts`）。
   它的价值不在测试本身，而在于它**强制保证"不存在只属于图谱的事实"**：
   - 这是将来能自由更换引擎的**唯一前提**；
   - 它也是唯一能提前发现"图谱语义泄漏回 L1"的机制——一旦泄漏，重建即失败；
   - 成本 ~0.5 天，且与任何后续图谱增强正交。

8. **该测试的判据在 Wave 1 执行期被实测修正过一次**（原判据**不可实现**）：
   原判据为「drop 5 张表 → 从 L1 重建 → **逐字段**一致」，两个独立原因使其无法成立——
   ① `pipeline/graph.ts` 的真实投影路径只注入 `now`、**不注入 `idFactory`**，
   id 回落随机值，任何重投影每行的 id/时间戳必然不同；
   ② 条 2 的墓碑不可由当前 L1 快照重建。
   改判为**三条可实现的断言**：① **零无来源不变量**（每个 node/fact/edge 来源非空且
   指向存活 L1 记录；`archived` 墓碑豁免**存活性**检查，但来源非空仍必须满足）；
   ② **负向验证**（绕过 `apply` 直接注入无来源行 → ①**必须失败**）；
   ③ **结构同构重建**（drop 5 张表 → 从 L1 重投影 → 归一 `id`/`createdAt`/`updatedAt`
   后逐字段一致）。**不改产品代码**。
   贯彻的判据：**判据不可实现时改判据，不改实现来迁就判据**——但必须先把"为什么不实现"
   查清并留底（见 `findings.md §10`）。

9. **不采用"再套一层抽象层"**：`GraphStore` 已是唯一访问边界，
   额外抽象没有验证价值——以冒烟测试替代（条 7）。为"将来可能换引擎"预留抽象层，
   是典型的为不确定的未来支付确定的成本。

组合关系：

- 条 1/2 是**前提**，条 3 是**推论**，条 4/5 是**在前提成立时的成本控制**，
  条 6 是**触发判据**，条 7/8 是**唯一现在要落的保险**。九条是同一条论证链，
  缺任一条都会让"暂不引入图数据库"退化为一个没有依据的偏好。
- 与 §F（图谱节点向量列）的关系：§F 是 **T0 内部的加法**（新增 `graph_node_vec`，
  与 `l1_vec` 同模式），**不触及引擎选型**；且必须**复用**既有的 FTS/向量能力探测与
  降级模式，不得硬依赖。§F 的启动条件是"出现语义实体消解需求"，与阶梯阈值无关。
- 与 §D 第 3 路（图谱检索路）的关系：正因为条 1/2 成立，把图谱接进检索链路才是安全的——
  图谱可重建，故它出问题时可回退重投影，而不是损坏事实源。
