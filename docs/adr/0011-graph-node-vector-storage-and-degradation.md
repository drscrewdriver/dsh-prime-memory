# 图谱节点向量列：存储地基与降级边界

背景：图谱的检索目前只有**词法加权打分**（`graph/search.ts` 的字段权重 name×6 … type×2），
没有向量列。于是"云深处"与"DeepRobotics"这类**语义等价但字面不同**的实体无法互相消解——
它们会被投影成两个节点，各自积累 facts，永远不会合并。

对照 L1：`l1_vec` 早已用 sqlite-vec 的 `vec0` 承载嵌入。图谱缺的**不是能力，是列**。

决定：

1. **本波只交付"存储与降级地基"，不含生产者与消费者。**
   `graph_node_vec` 目前有写入门（`upsertNodeVectors`）与检索门（`searchNodesByVector`），
   但**投影管线不会去算嵌入**。这是刻意的：真正的接线（什么时候嵌入、嵌入什么文本、
   命中后是否参与 RRF 融合）取决于"语义实体消解"这一需求的实际形态，
   先猜着做等于把一段没人验证的代码塞进投影主链路。
   **本条如实登记为"未完成"，不是"已完成的一波"**——它是 §F 的 T0 起点，不是终点。

2. **表结构与 `l1_vec` / `l0_vec` 同模式**：`vec0` 虚拟表 + `float[N] distance_metric=cosine`，
   列为 `node_id`(PK) / `embedding` / `updated_time`。
   "同模式"由**共用同一份编码**保证，而非口头约定：`vecToBuffer` / `isZeroVector`
   抽到中立的 `src/store/vec-utils.ts`。

   > 抽出去的直接原因是**模块环**：`sqlite.ts` 已经 import `GraphStore`，
   > 若让 `graph-store.ts` 反向 import `sqlite.ts`，环能跑但生死取决于加载顺序。
   > 那是隐式依赖，不是能留在代码里的东西。`sqlite.ts` 保留 re-export，外部导入点不变。

3. **能力探测复用既有结果，不新增一套。** 维度取自 `MemoryDb` 已经算好的
   `vecLoaded` / `dimensions`（`ensureVecLoaded` 的产物——它负责加载扩展、
   探测可用性、失败告警一次）。`GraphStore.init` 只接收一个 `{ dimensions }`。
   **部署未启用向量 → 不传 → 该路结构性不存在**：不建表、不告警、不抛。

   这个区分值得单独说：**"不建表"与"建一张空表"不是同一件事**。
   前者可断言（`tableExists === false`），后者会让"向量路到底有没有在跑"变成
   只能靠猜的问题——而猜错的代价是检索结果里静默少了一条路。

4. **降级必须内层消化：向量列失败不得拖垮整个图谱域。**
   `prepareNodeVec` 自带宽窄合宜的 `try/catch`，捕获后只停用向量路。
   外层 `GraphStore.init` 的 `catch` 是给"图谱表建不起来"用的
   （语义：图谱域整体 no-op）——**不该被一个可选的向量列触发**。
   若把两者合成一层，vec0 缺失（例如宿主环境没编译该扩展）会让词法检索、投影、
   裁决**全部陪葬**，而用户看到的只是一句"图谱初始化失败"。

5. **接口在停用态一律 no-op 返回，调用方无需判断 `nodeVecReady`。**
   `upsertNodeVectors` 返回 0、`searchNodesByVector` 返回 `[]`、`deleteNodeVectors` 静默返回。
   降级是**内建**的，不是"调用方记得先查能力位"——后者每多一个调用点就多一次漏判机会。
   `nodeVecReady` 仍然导出，但只用于**观测/日志**，不用于控制流。

6. **向量路命中不复用词法路的 `GraphNodeSearchResult`。**
   那个类型要求 `matchedFields`（命中在哪些字段）与 `matchReason`（中文解释），
   而向量检索**没有"命中哪个字段"这个概念**。塞一个空数组进去会违反该类型
   "无命中不返回、空数组不出现"的既有约定，把两种语义混成一个类型。
   故另立 `GraphNodeVecHit { node, score }`。

已知边界：

- **本波未验证"向量路真的能提升实体消解"**——因为还没有生产者。
  它的价值目前只有一个：把"图谱没有向量列"这个**结构性缺口**补成"有列但未接线"，
  使后续接线是一次增量而不是一次建表迁移。
- `graph_node_vec` **不参与图谱的可重建性不变量**（ADR-0007 的
  `tests/graph-rebuildability.test.ts`）。它是纯派生缓存：drop 掉再从节点重算即可，
  不存在"只属于向量表的事实"。这也是它可以被无条件 drop 而不触发迁移的原因。

组合关系：

- 与 ADR-0007（图谱是可重建派生投影）：向量列是**派生的派生**，
  比节点更可丢弃。它不需要自己的墓碑语义——节点没了，向量行按 `node_id` 直接删。
- 与 §D（RRF 四路）：若将来向量路要参与融合，它会成为**第 5 条列表**。
  届时需要同 `task_10` 的红线判据一样，证明它只重排候选、不引入新记录
  （否则"看起来相关但库里没有"的节点会凭空进入结果）。
- 与 §E（存储作用域）：图谱节点没有 `scope`，归属由其**来源记录**决定；
  向量路若接线，可见性过滤必须与 §E 在 `graphLane` 里落在同一层。
