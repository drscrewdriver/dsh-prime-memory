# 界面多语言（i18n）

> 一句话：界面文案走宿主 locale 服务，**key 就是中文原文**；拿不到 locale 服务时保持中文，绝不影响挂载。

## 为什么插件自己不提供语言开关

语言选择器属于宿主的 locale 插件（`@deepseek-ai/dsh-client-locale`）与语言包（例如
`@goodandready/dsh-russian-lang` 通过 `ctx.locale.addLanguage({ id: 'ru', … })` 注册俄语）。
本插件**只贡献自己的字典**，不自作主张注册语言 —— 否则设置里的语言列表会变成每个插件各加一项，
用户看到的选项取决于装了哪些插件。

宿主设置 → 通用 → 语言里选到某语言后，本插件的字典自动跟随；没有对应字典时逐级回退到英文，
再回退到中文原文。

## 文案怎么组织

**key = 中文原文**（gettext 式）：

```ts
import { tr } from './i18n.js';

tr('记忆库');                                  // 标签
tr('已扫描 {p1} 行，筛出 {p2} 条', { p1: n, p2: m }); // 带占位符
```

理由：抽取是机械的（不需要给 1000+ 条文案人工起 id），代码里的 key 自带语义，
翻译缺失时**优雅降级为中文原文**而不是露出裸 key。

`client/src/locales/` 下三个文件：

| 文件 | 内容 | 维护方式 |
|---|---|---|
| `keys.json` | key 全集（中文原文，排序稳定） | `node scripts/i18n-extract.mjs` 生成 |
| `en.ts` | 英文 | `node scripts/i18n-merge.mjs <译稿目录>` 生成 |
| `ru.ts` | 俄文 | 同上 |

`zh` 不单独存文件：运行期由 `en` 的 key 集派生为**恒等映射**（见 `client/src/i18n.ts`）。
这样中文用户在看英文回退链上永远不会被劫持成英文。

## 新增一条界面文案

1. 直接在组件里写中文，包 `tr(...)`：`<button>{tr('重建索引')}</button>`；
2. 重跑抽取 + 合并：

   ```bash
   node scripts/i18n-extract.mjs           # → client/src/locales/keys.json
   node scripts/i18n-merge.mjs <译稿目录>   # → en.ts / ru.ts（缺译的 key 会列出来）
   ```

3. `pnpm test tests/i18n-dict.test.ts` 会检查「key 全集被 en/ru 覆盖、占位符三语一致、
   译文不残留汉字」——新文案没翻译会在这里红。

## 新增一门语言

在 `client/src/i18n.ts` 的 `adopt()` 里加一行字典注册即可（key 集与 `en` 相同）：

```ts
svc.register(I18N_NS, 'de', de);
```

前提是该语言已被某个语言包 `addLanguage` 注册，用户才能在选择器里选到它。
本插件不自带语言选择器。

## 工具链

| 脚本 | 作用 |
|---|---|
| `scripts/i18n-extract.mjs` | 用 TypeScript AST 扫 `client/src`，抽出用户可见文案 → `keys.json` + `i18n-report.json` |
| `scripts/i18n-codemod.mjs` | 机械把中文文案包进 `tr(...)`（幂等）；结构位置**跳过**：对象键、`case` 标签、比较运算、`includes/startsWith/…` 参数、`import/export`、`console.*` 与 `throw` 诊断 |
| `scripts/i18n-merge.mjs` | **更新器**：以现有字典为基座，叠加译稿与 `scripts/i18n-overrides.json`，输出 `en.ts` / `ru.ts` 并报告缺失 key |
| `scripts/i18n-overrides.json` | 人工定稿层：术语裁决与「同形异义」拆分的落点（重跑 merge 不会丢） |
| `scripts/i18n-audit.mjs` | 静态审计：未走 `tr()` 的中文、字典硬伤（占位符/标点/长度/空壳/死 key）、`tr` 变量遮蔽、构建产物是否带齐字典。有 error 时退出码非 0 |

codemod 的边界是刻意的：**翻错会改行为的字符串一律不翻**。例如 `src/memory-types.ts` 里的
分类标签同时是存储值，属共享模块，不在本次 UI 改动范围内。

## 两个运行期陷阱（都已踩过）

1. **订阅早于 locale 就绪**：`useSyncExternalStore` 只在挂载时订阅一次。记忆库主页面在 boot 期就挂载，
   那一刻拿不到 locale 服务 —— 若订阅函数此时直接返回空操作，页面此后**永不重渲染**，
   界面冻结在中文（这正是「设置面板已英文、记忆库仍中文」的原因）。所以订阅走
   `subscribeLocale()`：服务未就绪时先登记，就绪后补订阅并回调一次。
2. **bundle 可能被宿主评估两次**：命名空间是全局单例，第二个实例的 `register` 必被拒
   （duplicate ns+locale）。若把注册与绑定写在同一个 `try` 里，第二个实例会永久退回中文。
   现在两者分开：注册失败只告警，`bind` 照常拿到字典。

## 已知边界

- **模块级常量活在 bundle 加载期**：`TABS` / `LANE_LABEL` 这类模块级标签表在 import 时求值，
  若 locale 服务在那一刻尚未就绪，它们会停在中文；**切换语言后整页刷新一次**即可全部对齐。
  面板根、pill 根、记忆库根都订阅了 locale revision，渲染期解析的文案是即时跟随的。
- **宿主侧槽位标签**（设置里「记忆」分节名、侧栏「记忆库」行）在注册时求值一次，
  切换语言后同样需要刷新才更新。
- **宿主半边的文案不在本次范围**：工具描述、日志、RPC 错误消息仍是中文（它们是给模型/开发者的），
  与界面语言无关。
- 译文是机助翻译 + 术语表约束的产物，长句欢迎在 PR 里直接改 `en.ts` / `ru.ts`。

## English (short version)

UI copy goes through the host locale service; **the key is the Chinese source string**, so extraction is
mechanical and a missing translation degrades to Chinese instead of leaking a raw key. The plugin
contributes three dictionaries (`keys.json`, `en.ts`, `ru.ts`) and never registers a language itself —
language selection belongs to the host locale plugin and language packs (`ctx.locale.addLanguage`).
`zh` is derived at runtime as the identity map over the `en` key set.

Add a string: write Chinese inside `tr(...)`, then re-run `scripts/i18n-extract.mjs` and
`scripts/i18n-merge.mjs`; `tests/i18n-dict.test.ts` enforces full coverage, placeholder parity and no
residual Han characters. Add a language: one `svc.register(I18N_NS, '<id>', dict)` line.

Known limits: module-level label tables and host-registered slot labels are evaluated once (refresh the
page after switching language); host-side messages (tool descriptions, logs, RPC errors) are out of scope.
